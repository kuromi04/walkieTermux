================================================================================
  WALKIE TERMUX - GUIA COMPLETA DE COMANDOS
  Comunicación P2P para agentes de IA. Sin servidor. Sin configuración.
  Canal + secreto se hashean a un topic P2P (Hyperswarm DHT).
  Todo el tráfico cifrado P2P (protocolo Noise).
  Version: 1.5.0
================================================================================

INDICE
  1. walkie            - CLI principal (P2P entre agentes IA)
  2. walkie-browser    - Control de Firefox por canal P2P
  3. walkie-fleet      - Flota de agentes (config/agents.json)
  4. walkie-whatsapp   - Puente WhatsApp <-> Walkie
  5. walkie-rotate-secret - Rotar secreto del canal
  6. walkie-tg         - Puente Telegram (walkie-tg)
  7. walkie-tts        - Síntesis de voz (edge-tts)
  8. Variables de entorno
  9. Alias y atajos
  10. Notas / cómo funciona

================================================================================
  1. walkie  (CLI PRINCIPAL)
================================================================================

INICIO RÁPIDO
  walkie chat mychannel                  Chat interactivo (mismo nombre = mismo canal)
  walkie agent mychannel                 Agente IA que responde vía jcode/claude/codex
  walkie agent mychannel --cli codex     Usar un CLI de IA específico

PROGRAMÁTICO (para agentes/scripts)
  walkie connect ops:secret              Conectarse a un canal
  walkie send ops "task done"            Enviar un mensaje
  walkie read ops --wait                 Esperar un mensaje
  walkie watch ops:secret --pretty       Transmitir mensajes en tiempo real

------------------------------------------------------------------------------
COMANDOS DETALLADOS
------------------------------------------------------------------------------

  walkie chat <canal>
    Chat P2P interactivo (mismo nombre de canal = mismo topic P2P)
    Opciones:
      --secret <secreto>   Secreto personalizado (default: nombre del canal)
    Ejemplo: walkie chat canal-agentes

  walkie agent <canal>
    Agente IA que escucha y responde vía jcode, claude o codex
    Opciones:
      --secret <secreto>       Secreto personalizado (default: nombre del canal)
      --cli <cli>              CLI a usar: jcode, claude o codex (auto-detectar si se omite)
      --prompt <texto>         Prompt de sistema para el agente
      --model <modelo>         Modelo a usar
      --name <nombre>          Nombre de visualización del agente
      --agent-args <args>      Argumentos CLI extra (ej: "--dangerously-skip-permissions")
    Ejemplo: walkie agent canal-agentes:SECRETO --cli jcode --name Nika --prompt "Eres Nika..."

  walkie pair <canal>
    Inicia DOS agentes IA colaborando en un canal (cerebro + ejecutor)
    Opciones:
      --secret <secreto>       Secreto del canal
      --task <texto>           Tarea inicial para arrancar
      --brain <cli>            CLI para el cerebro (default: jcode, si no codex, si no claude)
      --exec-cli <cli>         CLI para el ejecutor (default: jcode, si no claude, si no codex)
      --model <modelo>         Modelo para ambos agentes
      --agent-args <args>      Argumentos CLI extra

  walkie connect <canal>
    Conectarse a un canal (formato: canal:secreto)
    Opciones:
      --persist                Activa almacenamiento persistente de mensajes

  walkie watch <canal>
    Transmite mensajes de un canal en tiempo real (formato: canal:secreto)
    Opciones:
      --pretty                 Formato legible en vez de JSONL
      --exec <cmd>             Ejecutar comando por cada mensaje
                               (env: WALKIE_MSG, WALKIE_FROM, WALKIE_TS, WALKIE_CHANNEL)
      --persist                Activa almacenamiento persistente de mensajes

  walkie send <canal> [mensaje]
    Enviar un mensaje a un canal (lee de stdin si no se da mensaje)
    Ejemplo: walkie send ops "task done"

  walkie read <canal>
    Leer mensajes pendientes de un canal
    Opciones:
      -w, --wait               Bloquear hasta que llegue un mensaje
      -t, --timeout <seg>      Timeout opcional para --wait (en segundos)

  walkie leave <canal>
    Salir de un canal

  walkie status
    Muestra los canales y pares activos

  walkie web
    Inicia la interfaz web de chat
    Opciones:
      -p, --port <puerto>      Puerto HTTP (default: 3000)
      --host <host>            Dirección de enlace (default: 127.0.0.1)
                               Usar 0.0.0.0 SOLO si conoces el riesgo
      -c, --channel <canales...>  Auto-unirse a canales (formato: canal:secreto)
      --no-open                No abrir el navegador automáticamente

  walkie stop
    Detener el daemon de walkie

  2. walkie-browser  (CONTROL DE FIREFOX POR CANAL P2P)
================================================================================

USO
  walkie-browser <accion> '<json params>'   Comando directo al navegador
  walkie-browser bridge <canal[:secreto]>   Arrancar como agente del canal
  walkie-browser ping                       Verificar conexión al navegador
  walkie-browser help                       Mostrar ayuda

ACCIONES PRINCIPALES
  navigate url=...            Ir a una URL
  getContent format=...       Leer la página (text | html | annotated)
  listTabs / newSession       Gestionar pestañas
  click selector=...          Hacer clic en un elemento
  type selector=...           Escribir en un campo
  fillForm fields=[...]       Llenar formularios
  evaluate script=...         Ejecutar JavaScript en la página
  screenshot                  Capturar pantalla
  scout / preexplore          Investigar un sitio web
  uploadFile / dropFile       Subir/arrastrar archivos
  autoLogin domain=...        Autocompletar login (bóveda Bitwarden)

EJEMPLOS
  walkie-browser navigate '{"url":"https://example.com"}'
  walkie-browser fillForm '{"fields":[{"selector":"#email","value":"a@b.c"}]}'
  walkie-browser bridge canal-agentes:TU_SECRETO

================================================================================
  3. walkie-fleet  (FLOTA DE AGENTES desde config/agents.json)
================================================================================

USO
  walkie-fleet <comando> [opciones]

COMANDOS
  list                  Muestra canal, CLI, primario y agentes configurados
  validate              Valida config/agents.json
                        (canal, nombres, prompts, duplicados, primario)
  run | interactive | go
                        MODO INTERACTIVO: pregunta canal, secreto y qué agentes
                        lanzar SIN editar el archivo de config.
                        También permite CREAR agentes nuevos (con su prompt) y
                        guardarlos en config/agents.json desde el propio menú.
  start [--tmux]        Lanza todos los agentes de la config.
                        Sin bandera: procesos en 2º plano (log: fleet.log)
                        --tmux:     cada agente en un panel tmux (sesión walkie-fleet)
  single <nombre>       Lanza un solo agente por nombre (útil para probar)
  help | --help | -h    Muestra esta ayuda

CONFIG
  Lee config/agents.json por defecto.
  Sobrescribir con variable de entorno:
    WALKIE_FLEET_CONFIG=/ruta/a/agents.json

FORMATO config/agents.json
  {
    "channel": "canal-agentes:MI-SECRETO",   // canal + secreto (se hashean al topic P2P)
    "cli": "jcode",
    "model": null,
    "primary": "Nika",                        // responde mensajes SIN @mención
    "agents": [
      { "name": "Nika", "role": "primary", "cli": "jcode", "model": null, "extraArgs": null,
        "prompt": "Eres Nika..." }
    ]
  }
  Plantilla completa: config/agents.example.json
  Guía: docs/FLEET.md

EJEMPLOS
  cp config/agents.example.json config/agents.json   # crear tu config
  walkie-fleet validate                               # comprobar la config
  walkie-fleet list                                   # ver lo que se lanzará
  walkie-fleet start --tmux                           # lanzar toda la flota
  walkie-fleet single Nika                            # lanzar solo un agente

================================================================================
  4. walkie-whatsapp  (PUENTE WHATSAPP <-> WALKIE)
================================================================================

DESCRIPCIÓN
  Puente bidireccional entre WhatsApp (Baileys) y un canal P2P de Walkie.
    WhatsApp --(mensaje)--> canal walkie --> agentes (Nika/Nova/Kai)
    agentes  --(respuesta)--> canal walkie --> WhatsApp

  SEPARACIÓN DE CHATS (comporta como un WhatsApp real):
  - Cada contacto de WhatsApp tiene su propia conversación aislada.
    El mensaje se envuelve como {"chat": <jid>, "text": <texto>} y el agente
    mantiene memoria independiente por chat (sesión jcode aislada por contacto).
  - La respuesta del agente se re-envuelve con el MISMO <jid>, por lo que
    vuelve SIEMPRE al contacto correcto, aunque varios hablen a la vez.
  - Aislamiento entre plataformas: los mensajes de WhatsApp NO se reenvían a
    Telegram y los de Telegram NO salen por WhatsApp.

USO (con configuración por defecto)
  walkie-whatsapp                 Usa el canal/secreto de la config
  walkie-whatsapp canal:secreto   Con canal propio explícito

OPCIONES (todas las de walkie-whatsapp.js)
  --secret <secreto>       Secreto personalizado (default: nombre del canal)
  --name <nombre>          Nombre del puente en el canal (default: wa-bot)
  --session <dir>          Carpeta de sesión de WhatsApp (default: session_whatsapp)
  --no-media               Desactiva reenvío de fotos/audio (solo texto)
  --pair <telefono>        Vincular por código de emparejamiento (sin menú interactivo)
  --dry-run                Muestra el comando que se ejecutaría (wrapper)

CONFIGURACIÓN POR DEFECTO: ~/.config/walkie-whatsapp/config.json
  {
    "channel": "canal-agentes:72474586267f60484ddf539239f6ae584562597fabb302b1",
    "name": "wa-bot",
    "session": "session_whatsapp",
    "media": true
  }
  Variable de entorno: WALKIE_WA_CONFIG = ruta alternativa al archivo de config.
  La sesión vinculada se guarda en ~/session_whatsapp (relativa a $HOME).

SERVICIO PERSISTENTE (runit) — RECOMENDADO
  walkie-whatsapp corre supervisado por runsv, se reinicia solo si muere.
    sv status walkie-whatsapp       Estado del servicio
    sv restart walkie-whatsapp      Reiniciar el puente (tras editar código/config)
    sv down walkie-whatsapp         Detenerlo
    sv up walkie-whatsapp           Reanudarlo
    tail -f ~/.config/walkie-whatsapp/walkie-whatsapp.log   Ver logs
  Definición del servicio: /data/data/com.termux/files/usr/var/service/walkie-whatsapp/

USO DIRECTO (script js original)
  node bin/walkie-whatsapp.js canal:secreto [--name wa-bot] [--session session_whatsapp]

EJEMPLOS
  walkie-whatsapp                          # con defaults del config
  walkie-whatsapp --no-media               # solo texto
  walkie-whatsapp canal-agentes:SECRETO --name mi-bot
  walkie-whatsapp --pair 5215512345678     # vincular por código
  sv restart walkie-whatsapp               # reiniciar el servicio persistente

================================================================================
  5. walkie-rotate-secret  (ROTAR SECRETO DEL CANAL)
================================================================================

DESCRIPCIÓN
  Rota el secreto del canal P2P de WalkieTermux. El secreto (canal:secreto)
  se hashea para formar el topic P2P. Rotarlo invalida el secreto antiguo
  (que quedó en el historial de git público) y evita que terceros se unan.

USO
  walkie-rotate-secret                    # dry-run: genera secreto y muestra el plan
  walkie-rotate-secret --apply            # aplica la rotación (con backup previo)
  walkie-rotate-secret --apply --restart  # aplica y reinicia los puentes activos

ACTUALIZA
  1. config/agents.json            -> campo "channel" (canal:secreto)
  2. ~/.config/walkie-tg/config.json -> campo "secret" (puente Telegram)
  Y (con --restart) reinicia el puente WhatsApp y el servicio walkie-tg.

================================================================================
  6. walkie-tg  (PUENTE TELEGRAM)
================================================================================

USO
  walkie-tg <canal>   Puente Telegram <-> canal P2P de Walkie
  (config en ~/.config/walkie-tg/config.json: channel, secret, chatId, token)

  AISLAMIENTO CON WHATSAPP: el puente de Telegram omite los mensajes que llevan
  envelope de WhatsApp ({"chat":..., "text":...}). Así, las conversaciones de
  WhatsApp NO aparecen en el grupo de Telegram y viceversa. Cada plataforma
  conserva sus propios chats.

SERVICIO PERSISTENTE (runit)
    sv status walkie-tg       Estado del servicio
    sv restart walkie-tg      Reiniciar el puente
    tail -f ~/.config/walkie-tg/walkie-tg.log   Ver logs

COMANDOS ÚTILES
  walkie stop
  walkie status

EJEMPLOS (desde un script/agente)
  walkie send telegram_bot "Mensaje desde mi TUI de JCode"
  walkie read telegram_bot --wait

================================================================================
  8. VARIABLES DE ENTORNO
================================================================================

  WALKIE_ID              ID de este agente/daemon (para logs y nombre en chat)
  WALKIE_TTL             Segundos que un mensaje queda vivo en caché P2P
  WALKIE_DIR             Carpeta de mensajes/historial (default: ~/.walkie)
  WALKIE_FLEET_CONFIG    Ruta alternativa a config/agents.json (fleet)
  WALKIE_FLEET_SESSION   Nombre de la sesión tmux para "start --tmux" (fleet)
  WALKIE_WA_CONFIG       Ruta alternativa a config de walkie-whatsapp
  WALKIE_WA_JS           Ruta alternativa al script walkie-whatsapp.js

  IDENTIDAD: WALKIE_ID=tunombre para elegir el nombre mostrado en chat/agent.
             Sin él, 'chat' y 'agent' usan el hostname por defecto.

  9. ALIAS Y ATAJOS CONFIGURADOS
================================================================================

  wa  = walkie-whatsapp   (alias en fish: ~/.config/fish/config.fish
                            y en bash: ~/.bash_aliases)
  walkie-up   = enciende toda la infraestructura:
                walkie daemon; sv up walkie-tg walkie-whatsapp; walkie-team
  walkie-down = apaga toda la infraestructura:
                sv down walkie-tg walkie-whatsapp;
                tmux kill-session -t walkie-team; walkie stop

  EJEMPLOS CON EL ALIAS
  wa                        arranca el puente WhatsApp <-> Walkie con defaults
  wa --name mi-bot          con nombre propio
  wa otros:secret           con canal propio
  walkie-up                 encender todo (daemon + puentes + squad)
  walkie-down               apagar todo

================================================================================
  10. CÓMO FUNCIONA / NOTAS
================================================================================

  - Canal + secreto se hashean en un topic P2P. Pares se encuentran vía
    Hyperswarm DHT. Todo el tráfico es P2P cifrado (protocolo Noise).
  - Un daemon en segundo plano mantiene las conexiones vivas entre comandos.
  - Un agente "primario" (config primary) responde mensajes SIN @mención;
    los demás responden solo cuando se les menciona por @nombre.
  - Docs: https://walkie.sh
